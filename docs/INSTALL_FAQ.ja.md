# インストール・更新・アンインストール FAQ

YadoriLink エンジン（`yadorilink` コマンドラインと `yadorilink-daemon`）のインストール、
更新、アンインストールに関する回答です。あわせて [README](../README.ja.md) と
[Linux README](../packaging/linux/README.md) も参照してください。
英語版は [INSTALL_FAQ.md](INSTALL_FAQ.md) で、内容に差がある場合は英語版が正です。

現状: 現在のリリースはエンジンのみで、デスクトップアプリはまだありません。
以下で説明するワンライン インストーラーは作成とテストが済んでいますが、まだ公開されて
いません（README の「Planned」を参照）。そのため今は Linux パッケージまたはエンジン
バンドルからインストールします。このページはインストーラーの動作も説明しているので、
実行前に読めます。すべての OS で確認できていない記述は、テスト結果ではなく、ソフトウェアが
設計上どう動くかとして書いています。

## どの方法でインストールすればよいですか?

| 環境 | インストール方法 | 更新する主体 | 削除する主体 |
|---|---|---|---|
| Debian / Ubuntu | GitHub Releases の `.deb` | 新しい `.deb` をインストール | `sudo apt remove yadorilink` |
| macOS、Windows、Linux（現時点のエンジンのみ） | 展開するエンジンバンドル zip | あなた（新しいバンドルを展開） | あなた（フォルダーを削除） |
| macOS（Apple silicon）、Linux x86_64、Windows x64（公開後） | ワンライン インストーラー | `yadorilink self-update` のあと、表示されるインストーラーコマンド | `yadorilink uninstall`（Windows は `install.ps1 -Uninstall`） |
| macOS / Windows デスクトップアプリ（未リリース） | アプリ | アプリ | アプリ自身のアンインストール |

Docker イメージ、apt リポジトリ、Homebrew、WinGet は計画中で未公開です。このページの内容は
それらに依存しません。

すべてのデバイスを同じバージョンにしてください。どの方法でインストールしても、更新と削除は
同じ方法で行います。YadoriLink は、他のものが管理しているインストールを更新しません。
他のツールのコマンドは拒否され、代わりに使うべき手順が表示されます（終了コード 19）。

## ワンライン インストーラーは何をしますか?

```sh
curl -fsSL https://yadori.link/install.sh | sh          # macOS, Linux
irm https://yadori.link/install.ps1 | iex               # Windows (PowerShell 5.1 以降)
```

- ホームディレクトリ配下（既定は `~/.local`、Windows は `%LOCALAPPDATA%\YadoriLink`）に
  インストールします。`sudo` や管理者権限は使わず、デーモンも起動しません。
- チャンネル（`beta`、または `--channel nightly` で `nightly`）の署名付きリリース
  マニフェストをダウンロードし、スクリプトに組み込まれたリリース鍵で署名を検証します。
  続いてエンジンバンドルをダウンロードし、サイズと SHA-256 をマニフェストと、中身の
  すべてのファイルをバンドル自身のチェックサムと照合します。すべて通ったときだけ、
  `<prefix>/bin` の `yadorilink` と `yadorilink-daemon` を新しいバージョンに切り替えます。
  どれかの検証に失敗した場合は、メッセージを出して何も変更せず停止します。
- `--no-modify-path`（`-NoModifyPath`）を指定しない限り、`<prefix>/bin` をシェルの
  プロファイル（Windows ではユーザーの PATH）に追加します。
- `curl`、`unzip`、`awk`、および `sha256sum` または `shasum` が必要です。それ以外の OS や
  CPU（例: Alpine、32 ビット ARM）は終了コード 5 で拒否されます。

## 実行前にスクリプトを読めますか?

はい。ダウンロードして読んでから、そのファイルを実行してください:
`curl -fsSLo install.sh https://yadori.link/install.sh` のあと `sh install.sh`。
スクリプト冒頭に全オプションと実行手順が書かれています。`sh install.sh --help` でも
表示できます。

## ネットワークなし、または CI でインストールするには?

- CI: `sh install.sh --yes --no-modify-path --prefix "$RUNNER_TEMP/yadorilink"`
  （Windows は `-Yes -NoModifyPath -Prefix`）。質問せず、プロファイルも編集しません。
- オフライン: `--from FILE` は、事前にダウンロードした署名付きマニフェストファイルから
  インストールします。エンジンバンドル（macOS と Linux では署名検証プログラムも）を
  同じ場所に置いてください。ライブのマニフェストに到達できない場合、インストーラーは
  そのバージョンが取り下げられていないか確認できなかったと表示します。マニフェスト自体
  の検証は行われます。

## YadoriLink は誰が、どのように更新しますか?

Linux パッケージは、前回と同じ方法で新しい `.deb` をインストールします。エンジン
バンドルは、新しいバンドルを古いフォルダーに上書き展開するか、置き換えます。
どちらも YadoriLink が更新をダウンロードやインストールすることはなく、デーモンは
更新があることを知らせるだけです（`yadorilink update status`）。

コマンドライン（スクリプト）インストールでは、次のように自分で行います:

```sh
yadorilink self-update              # チャンネルが許可する最新バージョン
yadorilink self-update --version 1.2.0
```

`self-update` は、検証済みのチャンネルマニフェストを持つ稼働中のデーモンに、そのバージョン
が許可されているかを問い合わせます。許可されていれば、そのバージョンとあなたの prefix に
固定したインストーラーコマンドを表示します。そのコマンドを実行してください。インストーラーが
すべての検証をやり直し、一度の操作でバージョンを切り替え、次の更新まで前のバージョンを
ディスクに残します。`self-update` 自身は何もダウンロードもインストールもしません。

- 引数なしの `self-update` は段階的ロールアウトに従います。新しいバージョンがまだ
  提供されていない場合はそう表示します。`--version` ならそれでもインストールできます。
- 取り下げられたバージョンや最小サポートバージョン未満のバージョンは、何かを
  ダウンロードする前に拒否されます（終了コード 4）。
- 確認を完了できない場合（ネットワークなし、検証できないマニフェスト）は、その旨を表示し、
  最新であるとは言いません。
- デーモンは更新の存在を知らせるだけで（`yadorilink update status`）、何もインストール
  しません。

## バージョンを固定できますか? 古いバージョンに戻せますか?

Linux パッケージとエンジンバンドルでは、インストールするファイルを選ぶことでバージョンを
選びます。1.0 より前のリリースでは、古いバージョンが新しいバージョンの書いたデータを開ける
ことは保証されません（下記のダウングレードの注意を参照）。ワンライン インストーラーでは:

`--version X.Y.Z`（Windows は `-Version`、または環境変数 `YADORILINK_VERSION`）を
付けて実行します。署名付きのバージョン別マニフェストからそのバージョンをそのまま
インストールします。ただし、ライブのチャンネルマニフェストで取り下げられている場合や、
最小サポートバージョン未満の場合は拒否されます。`--force` で同じバージョンを再インストール
します。

ダウングレードはサポートされません。`--version` を付けても、インストーラーはインストール
済みのバージョンを古いものに置き換えません。古いバージョンが新しいバージョンの書いた
データを開けるか判断できないため、終了コード 6 で停止し、何も変更しません。アンインストール
して入れ直しても、残ったデータが古いバージョンで開けない可能性があるため、安全な回避策
ではありません。手動で戻す場合は、先に YadoriLink のデータディレクトリをバックアップし、
デバイスの設定をやり直す必要があるかもしれないと考えてください。何もインストールされて
いないマシンなら、`--version` で古いバージョンをインストールできます。

他のデバイスも、このデバイスと同じバージョンにしてください。

## アンインストールすると、ファイルはどうなりますか?

同期したフォルダーは常にそのまま残ります。アンインストールで削除されるのは YadoriLink の
プログラムであり、同期したフォルダーではありません。YadoriLink 自身のデータディレクトリ
（デバイスの識別情報、同期データベース、ファイルの保存済みバージョン、ダウンロード済み
コンテンツ）も残るため、後で再インストールすると同じデバイスとして続行します。他のデバイス
からは何も削除されず、アカウントも変更されません。

データディレクトリ:

| OS | データディレクトリ |
|---|---|
| macOS | `~/Library/Application Support/yadorilink` |
| Windows | `%USERPROFILE%\.yadorilink` |
| Linux | `~/.local/share/yadorilink`（または `$XDG_DATA_HOME/yadorilink`） |

`YADORILINK_CONFIG_DIR` で場所を変更できます。保存済みバージョンやダウンロード済み
コンテンツを含むため、大きくなることがあります。サインイン情報は別に保管されます:
macOS は Keychain、Windows は資格情報マネージャー、Linux はデータディレクトリ内の
`credentials.json` です。

## どうアンインストールしますか?

まず、必要ならこのコンピューターをアカウントから切断します（次の質問を参照）。そのうえで、
インストール方法に合う項目に従ってください。

**Linux パッケージ（`.deb`）。**

```sh
systemctl --user disable --now yadorilink-daemon
sudo apt remove yadorilink
```

パッケージを削除するだけでは、自分のユーザーで有効にしたバックグラウンドサービスは止まらない
ため、先に無効化してください。リポジトリのチェックアウトでは `./uninstall.sh` が両方を行い、
`./uninstall.sh --purge-data` はデータディレクトリも削除します。

**展開したエンジンバンドル。** `yadorilink daemon stop` を実行し、展開したフォルダーと、
追加した `PATH` の項目を削除します。バンドルはサービス、スケジュールタスク、シェル拡張を
インストールしないので、他に削除するものはありません。`yadorilink uninstall` は、自分が
入れたものではないため、このインストールを拒否します（終了コード 19）。

**ワンライン インストーラー。**

```sh
yadorilink uninstall --dry-run      # 削除対象を表示するだけで、何も変更しない
yadorilink uninstall                # 先に確認する。--yes で確認を省略
```

Windows ではインストーラーを `-Uninstall` 付きで実行します。シェル版インストーラーを使った
環境では `sh install.sh --uninstall` も使えます。

- 削除されるもの: `yadorilink` と `yadorilink-daemon` のリンク、インストールされた
  プログラムファイル（`<prefix>/share/yadorilink`）、インストーラーが追加した PATH の
  行。先にデーモンが停止されます。
- 残るもの: 同期したフォルダーとデータディレクトリ。
- 同期したフォルダーが安全だと判断できない場合（例: プログラムディレクトリの中にある
  フォルダー、読み取れないフォルダーレジストリ）、コマンドは何も削除せず拒否します。
  `--yes` ではこの確認を上書きできません。
- ダウンロードされていないファイル（On-Demand ファイル。デスクトップアプリが必要なため
  エンジンのみのリリースには存在しません）は、YadoriLink がなくなるとこのコンピューター
  では開けません。コマンドはその数を数え、1 件でもある場合、または数えられない場合は
  `--yes` なしでは拒否します。

インストール記録がない、または読み取れない場合、`uninstall` はその旨を表示して何も削除
しません。対処は `yadorilink doctor` が示します。`yadorilink uninstall` が見つけたその他の
インストール（パッケージマネージャー、アプリ、コンテナー）も、終了コード 19 と所有者側の
手順（例: `brew uninstall --cask yadorilink`、`winget uninstall yadorilink`）を示して
拒否されます。これらのチャンネルはまだ公開されていません。

## YadoriLink のデータも削除するには?

意図した場合だけ行ってください。同期したフォルダーは削除されません:

- macOS / Linux のスクリプトインストール: `yadorilink uninstall --purge-data` が、確認の
  あとでデータディレクトリを削除します。
- Linux パッケージ: リポジトリのチェックアウトで `./uninstall.sh --purge-data`、または
  `~/.local/share/yadorilink` を削除します。`XDG_DATA_HOME` や `YADORILINK_CONFIG_DIR`
  でデータディレクトリを移動している場合は、実際に使っているディレクトリを削除します。
- それ以外（展開したバンドル、Windows）: `yadorilink daemon stop` のあと、データ
  ディレクトリを手動で削除します。

macOS と Windows では、サインイン情報はデータディレクトリの外にあります。
`yadorilink uninstall --purge-data` はデータディレクトリと一緒にそれも削除します（デバイス鍵の
コピーを削除できない場合は、データディレクトリを削除する前に停止し、何が残っているかを
表示します）。データディレクトリを手動で削除する場合は、先に `yadorilink credentials purge`
を実行してください（デバイスも無効化するなら、その前に `yadorilink logout`）。ディレクトリ
を削除するだけではクリアされません。Linux では既定のサインインファイルがデータ
ディレクトリ内にあり、一緒に消えます。設定した場合の Secret Service のエントリは、どの
スクリプトも削除しません。キーリング管理ツールで削除してください。

データディレクトリを削除すると、他のデバイスが持っていない可能性のある保存済み
バージョンとダウンロード済みコンテンツも消えます。先に他のデバイスを確認してください。

## アンインストール後も、このコンピューターはアカウントに接続されたままですか?

はい。アンインストールはサインアウトも、サービスへの通知も行わないため、コンピューターは
アカウントに登録されたままです。このコンピューターを切断するには、アンインストール前に
`yadorilink logout` を実行するか、他のデバイスから
`yadorilink device remove <device-id>` で削除してください。削除したデバイスにすでにある
ファイルはそのまま残ります。

## 再インストールすればすべて元に戻りますか?

データディレクトリを残していれば、再インストールは同じデバイスとして続行します。識別情報、
フォルダー、履歴が再利用され、必要なのは再サインインだけの場合があります。削除していれば、
再インストールは初回インストールと同じです。新しいデバイスとして設定され、ファイルは他の
デバイスから再取得されます。データディレクトリがバックアップから復元したもの、またはコピー
の場合、YadoriLink は変更の署名を拒否して `database_restored` を報告します。
`yadorilink device start-over` で抜け出せ、ファイルと履歴は保持されます。

## インストーラーの終了コードの意味は?

| コード | 意味 |
|---|---|
| 0 | 完了、またはすでに最新 |
| 1 | その他の失敗 |
| 2 | 使い方の誤り（不明なオプション、`--from` のファイルがない） |
| 3 | ネットワークに接続できなかった |
| 4 | 署名、ハッシュ、リプレイ、取り下げのいずれかの検証でリリースが拒否された |
| 5 | 未対応の OS または CPU |
| 6 | インストール済みバージョンを古いバージョンで置き換えることを拒否した |
| 7 | インストール先ディレクトリに書き込めない |
| 19 | （`yadorilink self-update` / `uninstall`）このインストールは別のツールが管理している |
